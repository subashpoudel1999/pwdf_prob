Wildcat × MHRI Fusion — Setup Guide

A self-contained demo app: upload a burned area, run the USGS Wildcat post-fire debris-flow model, and fuse the result live into the ASBPA Multi-Hazard Resilience Index (MHRI) 1 km grid.

FLUTTER WEB PYTHON / FASTAPI GOOGLE EARTH ENGINE ~25–40 MIN SETUP
Dear Dr. Nawa Raj Pradhan,

This folder contains a complete, standalone copy of one module from our larger fire-hazard dashboard — the part that fuses Wildcat's debris-flow predictions into the ASBPA MHRI grid. Everything the app needs to run (the app's code, the server code, and the ~3.6 GB of hazard-index data it reads from) is already included in this folder, so nothing needs to be downloaded from anywhere except the two pieces of free software below (Flutter and Python). Please follow the steps in order — each one explains why it's needed, not just what to type. If anything doesn't match what you see on your screen, that's a good place to email me.

What you'll install first

1

Install the Flutter SDK required

The app's user interface (the map, the upload screen, the results panel) is written in Flutter, Google's toolkit for building apps that also run in a normal web browser.

Why you need this: without the Flutter SDK there is no way to compile or launch the interface — it's the equivalent of needing Node.js to run a JavaScript app.
  • Download Flutter from docs.flutter.dev/get-started/install/windows (choose Windows).
  • Unzip it so the folder sits at C:\flutter (this matches the shortcut script included in this folder — if you put it somewhere else, see the Troubleshooting section near the bottom).
  • Add C:\flutter\bin to your Windows PATH (the installer page above shows exactly how — it's a one-time setting in "Environment Variables").
  • Open a new Command Prompt and run:
flutter doctor

This checks your setup and tells you if anything else is missing. For this app you only need the Chrome entry to show a checkmark — entries about Android/Visual Studio can be ignored. Google Chrome itself must be installed (it almost certainly already is).

2

Install Python 3.11 (or 3.12) required

The "engine room" of the app — the part that actually runs the Wildcat hazard model and builds the MHRI grid — is a small Python server.

Why you need this: Flutter only draws the screen; all the real number-crunching (terrain analysis, satellite imagery, hazard-index math) happens in this separate Python program, which the Flutter app talks to over your own computer's local network address (localhost) — nothing leaves your machine except the Earth Engine requests in Step 4.
  • Download Python from python.org/downloads — version 3.11 or 3.12.
  • Important: on the first installer screen, tick "Add python.exe to PATH" before clicking Install.
  • Verify it worked by opening a new Command Prompt and running:
python --version
3

Get a free Google Earth Engine account required

The "Prepare" step inside the app downloads a 10 m elevation model and a burn-severity map for whatever area you draw, from Google Earth Engine (GEE) — a free satellite-data platform for research/non-commercial use.

Why you need this: we don't ship a worldwide elevation dataset (that would be terabytes) — instead the app fetches just the small piece it needs, on demand, from Google's servers, using your own free account.
  • Sign up at earthengine.google.com/signup with any Google account — approval is usually instant for non-commercial/research use.
  • Once approved, note down a Google Cloud project ID tied to that account — if you've never created one, Earth Engine's own onboarding flow will create a default one for you and show you its ID (it looks like ee-yourname or similar). You'll type this project ID into the app itself later — no need to write it down anywhere else.

Setting up this app's files

4

Install the Python server's dependencies

Open Command Prompt, navigate into this folder's backend directory, create an isolated Python environment, and install the required scientific packages:

cd "(path to this folder)\assets\backend"
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
Why a "venv"? it's a private, throwaway copy of Python just for this app, so its packages never conflict with anything else already on your computer.

This step downloads the geospatial libraries (GDAL, rasterio, GeoPandas) and the USGS wildcat hazard-modeling package, plus Google's Earth Engine client. It typically takes 5–15 minutes depending on your internet speed — that's normal, even if the screen looks idle for a while. If it ends with Successfully installed ..., you're done with this step.

5

Authenticate with Earth Engine (one-time)

Still in the same Command Prompt window (so the environment from Step 4 is active), run:

earthengine authenticate

This opens your web browser, asks you to sign in with the Google account from Step 3, and asks you to approve access. Once it says "Successfully saved authorization token", close that browser tab — you never need to repeat this step on this computer again.

Running the app

6

Double-click start_app.bat

In this folder, double-click start_app.bat. It will:

  • Start the Python server in the background (a black window — leave it open, it's the "engine room" from Step 4 running live).
  • Launch the app in a new Chrome window automatically.

The first launch can take a minute longer than usual while Flutter compiles the app. After that, just keep using the same double-click each time you want to open the app.

To close the app, simply close the Chrome tab and then close the black command window (or press Ctrl+C in it).

If double-clicking does nothing or shows an error about Flutter or Git Bash not being found, see Troubleshooting below for the manual two-window method — it always works as a fallback.

Using the app

A quick walkthrough

  • Step 1 — Upload your AOI: draw an Area of Interest (up to 700 km²) in any GIS tool (QGIS, ArcGIS, or the free browser tool geojson.io), export it as .geojson (or a zipped Shapefile), and upload it with a name, year, and approximate fire date.
  • Step 2 — Data download: paste your Google Cloud project ID from Step 3 and click "Start GEE Download" — this fetches the elevation model and burn-severity map for your area.
  • Step 3 — Run Wildcat: click "Run Wildcat" to model debris-flow probability for four standard rainfall intensities (16/20/24/40 mm/hr).
  • Step 4 — Results: toggle between the "Debris-flow" layer (per-catchment probability) and the "MHRI grid" layer (the fused 1 km hazard-index cells) on the map, switch rainfall scenarios, and click any shape for its full parameter breakdown.

If your AOI falls outside the 60-county ASBPA coverage area (coastal California / Oregon / Washington), you'll still get Wildcat's debris-flow results — just no MHRI fusion for that location, since that's the footprint the underlying hazard-index data covers.

Troubleshooting

start_app.bat says it can't find Flutter or Git Bash
Run the two pieces manually instead, in two separate Command Prompt windows:

Window 1 (server): 
cd "(this folder)\assets\backend"
.venv\Scripts\activate
python -m uvicorn main:app --port 8000
Window 2 (app), opened after Window 1 says it's running: 
cd "(this folder)"
flutter run -d chrome
Leave both windows open while using the app.
pip install fails on geopandas / rasterio / fiona
These normally install as ready-made "wheels" with no extra setup. If one still fails, the most reliable fix on Windows is installing just those three packages via Miniconda instead: 
conda create -n mhri python=3.11 -c conda-forge geopandas rasterio fiona shapely pyproj
conda activate mhri
pip install -r requirements.txt
Then use that mhri conda environment in place of .venv everywhere above.
"Backend failed to start" / port 8000 already in use
Something else on your computer is already using port 8000. Close any other copy of this app's server that might still be running (check for a leftover black Command Prompt window), or restart your computer if unsure, then try again.
GEE download step fails with an authentication or project error
Re-run earthengine authenticate (Step 5) to refresh your login, and double check the project ID you typed into the app matches exactly the one shown in your Earth Engine / Google Cloud account.
"Uploaded perimeter is ... km², which exceeds the 700 km² limit"
This cap exists because the MHRI fusion step samples 44 county-scale rasters per 1 km cell across your whole area — beyond ~700 km² that becomes slow. Draw or upload a smaller area.
Everything works but I want to confirm the server is alive
With the server running, open http://localhost:8000/health in a browser — it should show {"status":"ok"}.
